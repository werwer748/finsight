# SEO 전략

검색으로 들어온 사람이 샘플을 보고 가입하게 하는 것이 목표다. 이 문서는 **어떤 검색어를, 어떤 페이지로, 언제** 잡을지를 정한다. 페이지 안의 규칙(title, description, Open Graph, robots, sitemap)은 `docs/UI_GUIDE.md`의 `유입` 절이 정한다.

상태: 초안 (2026-10-12). 맨 아래 `미결정`의 세 가지가 정해지면 PRD의 개발 단계와 UI_GUIDE를 함께 고친다.

## 현재 상태
2026-10-12에 프로덕션을 직접 요청해 확인한 값이다.

| 항목 | 상태 |
|---|---|
| 주소 | `finsight-lovat-ten.vercel.app`. 자체 도메인 없음 |
| `/robots.txt`, `/sitemap.xml` | 404 |
| canonical, Open Graph | 없음 |

| description | 모든 페이지가 같은 문장 |
| 랜딩 본문 | h1과 리드문 두 문장뿐. `카드 명세서`, `소비 분석`, `가계부`가 없다 |
| 검색엔진 등록 | 소유 확인 태그와 파일이 없다. 색인됐는지 알 수 없다 |
| 응답 속도 | 반복 요청 기준 첫 바이트까지 0.15초 안팎. 시스템 글꼴. 손댈 것 없음 |
| 그 밖 | `lang="ko"`, 없는 주소는 404 상태 코드, 랜딩·샘플 정적 렌더링. 정상 |

## 검색 환경
- 한국 사용자는 네이버와 구글을 함께 쓴다. 둘은 다르게 접근한다.
  - 구글: 외부 사이트의 문서가 그대로 순위에 오른다. 우리 페이지로 긴 검색어를 잡는다.
  - 네이버: 정보를 찾는 검색은 블로그·카페·지식iN 영역이 먼저 나온다. 사이트는 브랜드 검색에서 확실히 나오게 하고, 정보성 검색은 네이버 블로그 글에서 사이트로 보낸다.
- 금융은 검색엔진이 신뢰를 엄격하게 따지는 분야다. 누가 운영하는지, 올린 파일을 어떻게 다루는지를 페이지에 밝히는 것이 순위와 가입 양쪽에 영향을 준다.
- `FinSight`는 해외 핀테크 여러 곳이 쓰는 이름이다 (뉴욕의 FINSIGHT, FinSight Ventures 등). 영문 이름만으로는 브랜드 검색에서 앞에 서기 어렵다. 한글 표기 `핀사이트`를 title과 본문에 함께 적는다. 네이버에서 `핀사이트`로 같은 이름의 국내 서비스가 나오는지는 아직 확인하지 않았다.

## 검색어
검색량은 확인하지 않았다. 아래는 가설이고, 가이드를 쓰기 전에 네이버 검색광고 키워드 도구와 Google 키워드 플래너로 확인한다.

| 묶음 | 검색하는 사람 | 예시 | 받는 페이지 | 판단 |
|---|---|---|---|---|
| A. 파일 구하기 | 내역을 엑셀로 받으려는 사람 | `○○카드 이용내역 엑셀 다운로드`, `○○은행 거래내역 엑셀 저장` | 기관별 가이드 | 주력 |
| B. 파일 정리하기 | 받은 엑셀을 정리하려는 사람 | `카드 내역 엑셀 정리`, `카드 사용내역 분석`, `거래내역 자동 분류` | 랜딩, 샘플 | 주력 |
| C. Pro 기능 | 새는 돈을 찾는 사람 | `정기결제 확인`, `구독 서비스 한번에 확인` | 랜딩의 요금제 섹션 | Phase 2 뒤 |
| D. 가계부 일반 | 가계부 앱을 고르는 사람 | `가계부 앱 추천`, `가계부 엑셀 양식` | 없음 | 하지 않음 |
| E. 브랜드 | 이름을 듣고 온 사람 | `핀사이트`, `FinSight 가계부` | 랜딩 | 기본 |

- A가 주력인 이유는 두 가지다. 검색한 사람이 곧 손에 쥘 파일이 FinSight의 입력이다. 그리고 이 글은 검색 유입이 없어도 써야 한다. 가입한 사람이 가장 먼저 막히는 곳이 파일을 구하는 단계다.
- A의 검색 결과에는 연말정산·종합소득세 준비용으로 쓴 개인 블로그 글이 나온다 (한 차례 검색해 본 것이라 근거가 약하다). 수요가 1월과 5월에 몰리는지 키워드 도구에서 함께 본다.
- B의 검색 결과에는 엑셀로 직접 만드는 강의와 서식이 나온다. 랜딩은 직접 만들지 않아도 된다는 점을 말한다.
- D를 하지 않는 이유: 계좌를 연동하는 가계부 앱과 엑셀 서식 글이 차지한 자리다. 랜딩에 `가계부`라는 낱말은 넣되 이 검색어를 노린 글은 쓰지 않는다.

## 단계

| 단계 | 내용 | 시점 |
|---|---|---|
| S0 | 도메인 결정 | 지금 |
| S1 | 기술 기반, 검색엔진 등록 | S0 직후 |
| S2 | 랜딩 본문 | S1과 함께. 요금제 섹션만 Phase 2 뒤 |
| S3 | 기관별 가이드 | Phase 3, 파서 보강과 함께 |
| S4 | 사이트 밖 유통 | 약관·개인정보처리방침이 올라간 뒤 |

### S0. 도메인
- 지금 주소는 Vercel이 붙인 임의의 하위 도메인이다. 거래 내역 파일을 올리라는 서비스의 주소로는 믿음이 가지 않고, 쌓이는 색인과 링크가 나중에 옮겨야 할 주소에 붙는다.
- 검색엔진 등록보다 먼저 정한다. 등록한 뒤에 주소를 바꾸면 리다이렉트, 두 웹마스터 도구 재등록, 순위가 다시 잡히는 기간이 든다.
- 도메인을 붙이면 `vercel.app` 주소는 새 도메인으로 리다이렉트한다.
- 사이트 주소는 코드 한 곳에서만 읽는다. `metadataBase`, canonical, sitemap, robots가 모두 그 값을 쓴다.

### S1. 기술 기반과 등록
UI_GUIDE `유입` 절의 `[P3]` 세 항목(랜딩 title과 페이지별 description, Open Graph, robots와 sitemap)에 아래를 더한다.

- `metadataBase`와 페이지별 canonical.
- `/login`, `/signup`에 title을 준다. `화면 이름 | FinSight` 규칙은 지금도 적용 대상인데 두 페이지에 빠져 있다. 루트 레이아웃의 `title.template`으로 한 번에 맞춘다.
- robots는 `/dashboard`, `/api/`, `/auth/`를 막는다.
- 랜딩에 `WebSite` JSON-LD(name `FinSight`, alternateName `핀사이트`)를 넣어 검색 결과에 나오는 사이트 이름을 정한다. 다른 유형은 넣지 않는다. FAQ·HowTo 리치 결과는 구글이 일반 사이트에 보여 주지 않고, `SoftwareApplication` 리치 결과는 실제 평점이 있어야 한다.
- Open Graph 이미지는 카카오톡으로 공유했을 때의 미리보기에 그대로 쓰인다.
- Google Search Console과 네이버 서치어드바이저에 등록하고 사이트맵을 제출한다. 소유 확인은 `metadata.verification`으로 한다 (네이버는 `other`의 `naver-site-verification`). Bing 웹마스터 도구는 Search Console에서 가져오기로 등록한다 (선택).

### S2. 랜딩 본문
- 섹션은 UI_GUIDE `랜딩` 절의 순서를 그대로 따른다 (히어로, 대시보드 미리보기, 쓰는 방법 3단계, 안심 문구, 요금제, 자주 묻는 질문, 가입 버튼). 섹션을 새로 만들지 않는다.
- h1과 리드문에 `카드 명세서`, `소비 분석`을 넣는다. UI_GUIDE `유입` 절의 규칙인데 지금 빠져 있다. `가계부`도 title이나 리드문에 한 번 넣고, 그 절의 낱말 목록에 추가한다.
- title 초안: `FinSight(핀사이트) | 카드 명세서·거래 내역 엑셀로 보는 소비 분석`
- description 초안: `은행·카드사에서 내려받은 거래 내역 엑셀·CSV 파일을 올리면 자동으로 분류해 지출을 한눈에 보여 주는 가계부예요. 은행 아이디나 비밀번호 없이 무료로 시작하세요.`
- 쓰는 방법 3단계의 `파일 내려받기`와 자주 묻는 질문이 가이드(S3)로 가는 내부 링크 자리다.
- `/sample`에는 고유한 description을 준다.

### S3. 기관별 가이드
- 주소는 `/guides/기관`, 목록은 `/guides`. 기관마다 한 페이지에 세 가지를 쓴다. 어느 메뉴에서 어떤 형식으로 받는지(PC와 앱), 그 파일을 올리면 무엇이 나오는지, 확인한 날짜.
- UI_GUIDE `대시보드` 절은 이 안내를 Phase 3에 빈 상태에 접어 두기로 했다. 로그인 뒤의 화면은 검색엔진이 읽지 못한다. 내용은 공개 페이지에 쓰고 빈 상태에서는 그 페이지로 링크한다. 쓰는 글은 같고 놓는 자리만 바뀐다.
- 직접 받아 본 기관만 쓴다. 메뉴 경로를 확인하지 않은 글, LLM으로 채운 글은 올리지 않는다. 틀린 안내는 방금 가입한 사람을 막는다. 기관 이름만 바꾼 같은 내용의 페이지는 구글이 스팸으로 본다.
- Phase 3에서 파서를 보강하는 순서대로 3~5곳을 먼저 쓴다. 올리고 4~8주 동안 Search Console의 노출을 본 뒤 나머지를 쓸지 정한다.
- `/guides` 목록이 지원 기관 목록 역할을 한다. 실제 파일이 읽히는 것을 확인한 기관만 올린다.
- 가이드는 sitemap에 넣는다.

### S4. 사이트 밖 유통
- 네이버 블로그: 가이드마다 요약 글을 한 편 쓰고 전체 내용은 사이트로 링크한다. 네이버의 정보성 검색을 받는 통로다. 계속 글을 쓰는 시간이 들므로, 운영할지는 S3의 결과를 보고 정한다.
- 출시 글: 디스콰이엇, GeekNews 같은 제작자 커뮤니티에 올린다. 첫 링크와 첫 사용자를 얻는다.
- 약관과 개인정보처리방침이 올라가기 전에는 사람을 끌어오지 않는다. 금융 내역을 받는 서비스다.

## 측정
- Google Search Console, 네이버 서치어드바이저: 색인된 페이지 수, 검색어별 노출과 클릭.
- PostHog: 검색 유입에서 `/sample`, 가입, 첫 업로드까지의 흐름. 거래 데이터와 개인정보는 보내지 않는다 (CLAUDE.md CRITICAL).

| 시점 | 확인할 것 | 안 되면 |
|---|---|---|
| S1 뒤 2주 | 공개 페이지가 모두 색인됐는가. `핀사이트` 검색에 나오는가 | Search Console 색인 보고서의 사유를 본다 |
| 가이드 첫 묶음 뒤 4~8주 | 가이드에 노출이 생기는가 | 검색어 가설을 다시 보고 나머지 가이드는 미룬다 |
| 분기마다 | 검색 유입이 가입으로 이어지는가 | 랜딩과 샘플의 문구를 고친다 |

## 하지 않는 것
- 재테크 일반 주제의 블로그, `가계부` 대표 검색어 경쟁.
- LLM으로 대량 생성한 페이지, 기관 이름만 바꾼 복제 페이지.
- 링크 구매, 검색어 반복 삽입.
- 영문·다국어 페이지 (PRD 제외 사항).
- 후기·평점 구조화 데이터. 실제 값이 생기기 전에는 넣지 않는다.

## 미결정
1. **도메인을 살 것인가, 이름은 무엇으로 할 것인가.** 권장: 산다. S1보다 먼저.
2. **S0~S2를 지금 독립 phase로 당길 것인가, Phase 3에 둘 것인가.** 권장: 지금 한다. Pro·결제와 겹치는 코드가 없고, 새 주소가 색인되고 자리 잡는 데 몇 주가 걸려 출시 때 시작하면 출시 직후의 검색 유입이 비어 있다. 반대 근거: PRD는 현재 phase에 없는 것을 미리 만들지 않는다. 당기면 UI_GUIDE `유입` 절의 `[P3]` 표시를 고친다.
3. **가이드를 공개 페이지로 낼 것인가.** 권장: 낸다. 정하면 UI_GUIDE의 `대시보드` 절(빈 상태에 접어 둔다)과 `유입` 절(sitemap에는 `/`와 `/sample`만)을 고친다.
