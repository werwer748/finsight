# UI/UX 가이드

FinSight의 화면을 만들고 고칠 때 따르는 기준. 목표는 두 가지다. 처음 온 사람이 무엇을 해 주는 서비스인지 바로 알고 가입하는 것, 써 본 사람이 망설이지 않고 Pro를 결제하는 것.

디자인 원칙은 Figma의 [UI 디자인 원칙 7가지](https://www.figma.com/ko-kr/resource-library/ui-design-principles/)(계층 구조, 점진적 공개, 일관성, 대비, 접근성, 근접성, 정렬)를 따른다. 이 문서는 그 원칙을 FinSight에서 확인할 수 있는 규칙으로 옮긴 것이다.

## 범위와 우선순위
- 이 문서는 **어떻게 만들지**를 정한다. **무엇을 언제 만들지**는 PRD와 step 파일이 정한다. 여기 적혀 있다는 이유로 step에 없는 화면·섹션·버튼을 추가하지 않는다.
- `[P2]`, `[P3]`가 붙은 항목은 그 phase에서 해당 화면을 만들 때 적용한다. 표시가 없는 항목은 지금부터 적용한다.
- 내용이 충돌하면 step 파일, PRD, 이 문서 순으로 따른다.
- 토큰, 컴포넌트 variant, 버튼 문구를 새로 만들거나 바꾸면 같은 변경에서 이 문서도 고친다.

## 전환 흐름

```
랜딩(/) → 샘플(/sample) → 가입(/signup) → 첫 업로드 → 대시보드 → 잠금 카드·한도 안내 [P2] → 결제 [P2]
```

| 화면 | 사용자의 질문 | 화면이 줄 답 | 주요 동작 |
|---|---|---|---|
| 랜딩 | 뭘 해 주는 거지? 내 정보는 안전한가? | 한 문장 제목, 필요한 건 파일뿐 | `무료로 시작하기` |
| 샘플 | 내 내역으로 보면 어떻게 나오지? | 실제와 같은 대시보드 | `무료로 시작하기` |
| 가입 | 오래 걸리나? | 입력 3개 | `가입하기` |
| 대시보드 (내역 없음) | 무엇을 올리면 되지? | 파일 형식, 업로드 폼 | `올리기` |
| 대시보드 (내역 있음) | 얼마를 어디에 썼지? | 총 지출, 카테고리 | 없음 (읽는 화면) |
| 잠금 카드·한도 안내 [P2] | 돈을 내면 뭐가 열리지? 얼마지? | 열리는 기능, 월 금액 | `Pro로 업그레이드` |
| 결제 후 복귀 [P2] | 결제가 된 건가? | 잠금이 풀린 대시보드 | 없음 |

- 가치를 먼저 보여 주고 그다음에 요청한다. 샘플은 가입 전에, 무료 대시보드는 결제 전에 본다.
- 화면마다 주요 동작은 하나다. 위 표에 없는 동작을 그 화면의 주요 버튼으로 만들지 않는다.
- 다음 단계로 가는 길을 끊지 않는다. 이메일 확인을 마치면 대시보드로, 대시보드가 비어 있으면 업로드 폼이 바로 보인다.

## 원칙별 규칙

### 1. 계층 구조
- 화면에서 가장 큰 요소는 하나다. 랜딩은 h1, 대시보드는 `총 지출` 금액.
- 요약에서 상세 순으로 놓는다. 대시보드는 기간, 합계, 카테고리, 거래 내역 순이다.
- 글자의 위계는 세 단계만 쓴다. 제목·숫자(`font-bold`), 본문, 보조(`text-sm text-muted`).
- 폭 360px 화면에서 h1과 주요 버튼이 스크롤 없이 보여야 한다.

### 2. 점진적 공개
- 한 화면에서 한 가지 일만 시킨다. 가입 폼에는 가입에 필요한 입력만 둔다.
- 지금 필요하지 않은 설명은 `<details>`로 접어 둔다.
- 기다리는 동작은 진행 중임을 보여 준다. 버튼을 비활성화하고, 업로드나 결제 이동처럼 2초 넘게 걸릴 수 있으면 문구도 진행형(`올리는 중…`)으로 바꾼다.
- Pro 기능은 잠금 카드로 있다는 것만 알리고 설명은 한 줄로 끝낸다. [P2]
- 한도는 닿기 전에 알리고(`무료 플랜은 한 달에 한 번 올릴 수 있어요`), 업그레이드 안내는 한도에 닿은 그 자리에 둔다. [P2]

### 3. 일관성
- 버튼, 입력, 카드는 `src/components/ui/`의 `Button`·`ButtonLink`·`Input`·`Card`만 쓴다. 페이지나 다른 컴포넌트에서 `<button>`에 직접 스타일을 입히지 않는다.
- 색과 모서리는 `src/app/globals.css`의 토큰만 쓴다. Tailwind 기본 팔레트(`text-gray-500`, `bg-blue-600`)와 hex 값을 컴포넌트에 쓰지 않는다. 예외는 `primary` 배경 위의 `text-white` 하나다.
- 같은 동작은 어디서나 같은 문구와 같은 모양이다. 아래 [버튼 문구](#버튼-문구) 표를 따른다.
- 샘플과 실제 대시보드는 같은 컴포넌트(`DashboardView`)에 다른 데이터를 넣어 그린다.
- 잠금 카드는 Pro로 올렸을 때 그 섹션이 놓일 자리에 같은 순서로 둔다. 결제하면 그 자리에서 열려야 한다. [P2]

### 4. 대비
- `primary` 색은 눌러야 할 것과 읽어야 할 데이터에만 쓴다. 주요 버튼, 글 속 링크, 차트 막대, 포커스 표시가 전부다. 제목, 본문, 장식에는 쓰지 않는다.
- 한 영역(헤더, 히어로, 폼, 카드)에 `primary` 버튼은 하나다. 버튼 두 개가 나란히 있으면 하나는 `secondary`나 `ghost`다.
- `danger` 색은 오류 문구와 오류가 난 입력의 테두리에만 쓴다.
- 지출·수입·증감을 빨강과 파랑으로 나누지 않는다. 이유: 국내 금융 화면은 오름을 빨강으로 표시해 색의 뜻이 사람마다 다르다. 부호(`+`, `-`)와 글자(`지난달보다 12% 늘었어요`)로 표시한다.

### 5. 접근성
- 글자와 배경의 대비는 4.5:1 이상이다. `background`·`surface` 위의 글자색은 `foreground`, `muted`, `primary`, `danger`만 쓴다 (모두 4.6:1 이상). `border` 색은 글자에 쓰지 않는다.
- 색만으로 뜻을 전하지 않는다. 오류는 문구로, 증감은 부호로도 읽혀야 한다.
- 누를 수 있는 것은 `<button>`과 `<a>`다. `div`에 `onClick`을 달지 않는다.
- 포커스 표시(`focus-visible:outline-*`)를 지우지 않는다. 키보드만으로 화면의 주요 동작을 끝낼 수 있어야 한다.
- 입력에는 항상 보이는 라벨이 있다. placeholder는 형식 힌트(`8자 이상`)에만 쓴다. 오류는 입력 바로 아래에 두고 `aria-describedby`로 잇는다.
- 동작의 결과는 오류면 `role="alert"`, 성공이면 `role="status"`로 알린다.
- 페이지마다 h1은 하나이고 제목 단계를 건너뛰지 않는다.
- 뜻이 있는 이미지에는 `alt`를, 장식에는 `aria-hidden="true"`를 준다. 차트의 값은 글자로도 읽혀야 한다.
- 누르는 대상의 높이는 40px 이상(`Button`의 `md`)이고 글자는 `text-sm`보다 작게 쓰지 않는다.
- 컴포넌트 테스트는 `getByRole`, `getByLabelText`로 요소를 찾는다. `getByTestId`는 쓰지 않는다. 이유: 역할과 라벨이 사라지면 테스트가 먼저 깨진다.

### 6. 근접성
- 묶음 안의 간격은 묶음 사이의 간격보다 좁다. 라벨·입력·오류는 `gap-1.5`, 폼의 필드 사이는 `gap-4`, 카드와 섹션 사이는 `gap-6` 이상.
- 숫자와 그 이름표, 버튼과 그 버튼이 처리하는 대상은 붙여 둔다. 업로드 결과 문구는 업로드 폼 안에 나온다.
- 주요 동작과 되돌리기 번거로운 동작(`로그아웃`, `구독 관리`)은 떨어뜨려 둔다.

### 7. 정렬
- 본문은 왼쪽 정렬이다. 가운데 정렬은 랜딩 히어로와 빈 상태에만 쓴다.
- 표의 금액 열은 오른쪽 정렬에 `tabular-nums`를 쓴다. 크게 보이는 단독 숫자에는 `tabular-nums`를 쓰지 않는다.
- 모든 화면이 같은 컨테이너 폭과 좌우 여백을 쓴다 (아래 표).
- 한국어 제목과 문단에는 `break-keep`을 줘 단어 중간에서 줄이 바뀌지 않게 한다.

## 토큰

색은 `src/app/globals.css`의 `@theme`에 정의돼 있다. 색을 추가하려면 `@theme`와 이 표를 함께 고친다. 라이트 모드만 지원하므로 `dark:`를 쓰지 않는다.

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `background` | `#ffffff` | 랜딩 배경, 카드 |
| `surface` | `#f9fafb` | 앱 내부 페이지 배경, hover |
| `foreground` | `#111827` | 제목, 본문, 숫자 |
| `muted` | `#6b7280` | 보조 설명, placeholder |
| `border` | `#e5e7eb` | 테두리, 구분선 |
| `primary` / `primary-hover` | `#2563eb` / `#1d4ed8` | 주요 버튼, 링크, 차트 막대, 포커스 |
| `danger` | `#dc2626` | 오류 |

| 글자 | 클래스 |
|---|---|
| 랜딩 h1 | `text-4xl sm:text-5xl font-bold tracking-tight` |
| 앱 페이지 h1 | `text-2xl font-bold tracking-tight` |
| 섹션 h2 | `text-xl font-bold tracking-tight` |
| 대표 숫자 (화면에 하나) | `text-5xl` 이상, `font-bold` |
| 보조 숫자 | `text-2xl` |
| 랜딩 리드문 | `text-lg text-muted` |
| 본문 | `text-base` |
| 보조 설명, 라벨, 오류 | `text-sm` |

| 배치 | 클래스 |
|---|---|
| 좌우 여백 | `px-4 sm:px-6` |
| 컨테이너 | 헤더·푸터·앱 `max-w-5xl`, 랜딩 글 `max-w-3xl`, 가입·로그인 카드 `max-w-sm` |
| 헤더 높이 | `h-16` |
| 카드 안쪽 여백 | `p-6` |
| 모서리 | `rounded-base` |

모바일을 먼저 쓰고 `sm:`에서 넓힌다. 폭 360px에서 페이지가 가로로 스크롤되면 안 된다. 넘치는 표는 표만 `overflow-x-auto`로 감싼다.

## 컴포넌트

- **Button**: variant는 `primary`(그 영역의 주요 동작), `secondary`(나란히 놓인 두 번째 동작), `ghost`(헤더의 가벼운 동작) 세 가지다. size는 랜딩·샘플의 가입 버튼이 `lg`, 나머지는 `md`. 페이지 이동은 `ButtonLink`, 그 밖의 동작은 `Button`을 쓴다.
- **Card**: 테두리로만 구분하고 그림자를 쓰지 않는다. 카드 안에 카드를 넣지 않는다. 앱 내부는 `surface` 배경 위에 흰 카드를 올린다.
- **상태**: 데이터를 보여 주는 화면은 네 가지 상태를 모두 가진다.
  - 빈 상태: 무엇이 비었는지와 다음에 할 일을 말한다. 그 동작(버튼이나 폼)이 같은 화면에 보여야 한다.
  - 진행 중: 버튼 비활성화와 진행형 문구.
  - 오류: 무슨 일이 있었는지와 어떻게 하면 되는지. 다시 할 방법이 같이 있어야 한다.
  - 성공: 결과를 숫자로 말한다 (`12건을 저장했어요.`).
- **숫자**: 금액은 `1,234,000원`, 날짜는 `2026.08.14`로 쓴다. 컴포넌트에서 직접 포맷하지 않고 `src/lib/format.ts`의 `formatWon`, `formatDate`를 쓴다 (Phase 1에서 추가).
- **차트**: 가로 막대를 Tailwind로 그리고 값을 글자로 함께 적는다. 색은 `primary` 한 가지이고, 여러 항목 중 하나를 강조할 때만 나머지를 무채색으로 둔다. 도넛·파이 차트와 차트 라이브러리는 쓰지 않는다 (ADR-009).

## 화면별 설계

### 랜딩 `/`
- 히어로에 다섯 가지가 있다. 무엇을 해 주는지 말하는 h1, 무엇을 올리면 무엇이 나오는지 말하는 리드문, `무료로 시작하기`, `샘플 먼저 보기`, 로그인 링크.
- 헤더에는 로고, `로그인`, `시작하기`만 둔다.
- 섹션을 더할 때는 이 순서로 쌓는다. 히어로, 대시보드 화면 미리보기, 쓰는 방법 3단계(파일 내려받기, 올리기, 보기), 안심 문구, 요금제 [P2], 자주 묻는 질문, 가입 버튼. 섹션마다 h2 하나와 전할 말 하나만 둔다.
- 안심 문구에는 코드가 보장하는 사실만 쓴다. 예: `은행 아이디나 비밀번호는 필요 없어요. 내려받은 파일만 올리면 돼요.`, `금액은 AI가 아니라 코드가 계산해요.` ADR에 트레이드오프로 남은 부분은 단정하지 않는다.
- 후기, 사용자 수, 언론 로고는 실제 값이 있을 때만 넣는다.

### 샘플 `/sample`
- 가상 데이터라는 안내와 `무료로 시작하기`가 화면 맨 위에 있다.
- 가입도 Claude 호출도 없이 정적으로 뜬다.
- Pro 섹션은 잠그지 않고 열린 모습으로 보여 준다. AI 인사이트는 미리 써 둔 고정 문장이다. [P2]

### 가입·로그인
- 헤더 메뉴 없이 로고와 폼만 둔다. 가입에 필요하지 않은 입력을 추가하지 않는다.
- 오류가 나도 입력한 이메일은 남긴다. 오류는 해당 입력 아래에 나온다.
- 가입 직후에는 받은 메일의 링크를 눌러야 한다는 것을 알려 준다.

### 대시보드 `/dashboard`
- 업로드 폼은 내역이 있든 없든 맨 위에 있다. 다음 달 파일을 올리러 다시 온 사람이 찾지 않게 한다.
- 기간을 항상 보여 준다. 내역이 언제까지인지 알아야 다음 파일을 올린다.
- 무료 범위 안에서 화면이 완결돼야 한다. 무료 기능을 일부러 불편하게 만들지 않는다.
- 섹션 순서는 기간, 합계, 카테고리 차트, Pro 분석, 거래 내역이다. 긴 거래 표가 Pro 분석을 밀어내지 않게 표를 맨 아래에 둔다. [P2]
- 은행·카드사별 파일 내려받는 방법은 빈 상태에 접어서 둔다. [P3]

### 업그레이드와 결제 [P2]
- 진입점은 세 곳이고 모두 같은 결제 시작 동작으로 이어진다.
  - 잠금 카드: 기능 이름, 얻는 것을 말하는 한 줄(`매달 빠져나가는 구독을 찾아 드려요`), `Pro로 업그레이드` 버튼. 가짜 수치나 흐리게 가린 가짜 차트를 넣지 않는다.
  - 한도 안내: 업로드 한도, 조회 기간, 표의 검색·필터 자리에 한 줄 문구와 링크로 둔다. 잠긴 기능을 비활성 컨트롤로 흉내 내지 않는다.
  - 대시보드 헤더: 무료 사용자에게는 `Pro로 업그레이드`(`secondary`), Pro 사용자에게는 `Pro` 표시와 `구독 관리` 링크.
- 업그레이드 버튼을 누르기 전에 월 금액과 매달 결제된다는 사실이 화면에 보여야 한다. 금액은 코드 한 곳에서만 정의한다.
- 버튼을 누르면 비활성화하고 `결제 페이지로 이동 중…`으로 바꾼다.
- 결제를 마치면 대시보드로 돌아온다. 플랜이 반영됐으면 잠금이 풀린 화면과 `Pro가 시작됐어요.`를 보여 준다. 웹훅이 아직 오지 않았으면 `결제를 확인하고 있어요.`를 보여 준다. 화면이 먼저 잠금을 풀지 않는다. 권한은 서버가 DB의 플랜으로 판단한다.
- 결제를 그만두고 돌아오면 보던 대시보드를 그대로 보여 준다. `결제가 완료되지 않았어요. 언제든 다시 시도할 수 있어요.`
- 해지 경로를 숨기지 않는다. `구독 관리`는 헤더에서 한 번에 닿아야 한다.

## 문구
- 해요체로 짧게 쓴다. 제목과 버튼에는 마침표를 찍지 않고 문장으로 된 설명과 오류에는 찍는다.
- 버튼 문구는 누르면 일어나는 일을 말한다. `확인`, `제출`, `클릭`을 쓰지 않는다.
- 내부 용어를 화면에 내보내지 않는다 (`파싱 실패` 대신 `파일을 읽지 못했어요.`). 서버 예외의 message를 그대로 보여 주지 않는다.
- 오류 문구는 무슨 일이 있었는지와 어떻게 하면 되는지를 한두 문장으로 말한다. 사용자를 탓하지 않는다.
- 용어는 하나로 통일한다. `거래 내역`, `카테고리`, `총 지출`, `총 수입`, `무료`, `Pro`.

### 버튼 문구

| 동작 | 문구 | 모양 |
|---|---|---|
| 가입 유도 (랜딩, 샘플) | `무료로 시작하기` | `primary` `lg` |
| 가입 유도 (랜딩 헤더) | `시작하기` | `primary` `md` |
| 샘플 보기 | `샘플 먼저 보기` | `secondary` `lg` |
| 가입 폼 제출 | `가입하기` | `primary` `fullWidth` |
| 로그인 | `로그인` | 폼에서는 `primary` `fullWidth`, 헤더에서는 `ghost` |
| 파일 업로드 | `올리기`, 진행 중 `올리는 중…` | `primary` `md` |
| 다시 시도 | `다시 시도` | `primary` `md` |
| 업그레이드 [P2] | `Pro로 업그레이드`, 진행 중 `결제 페이지로 이동 중…` | 잠금 카드 `primary`, 헤더 `secondary`, 한도 안내는 링크 |
| 구독 관리 [P2] | `구독 관리` | 링크 |
| 로그아웃 | `로그아웃` | `ghost` |

## 유입
- 랜딩과 샘플은 서버 컴포넌트로 만들어 정적으로 렌더링한다. 글은 이미지가 아니라 HTML 텍스트로 쓴다.
- 랜딩의 h1과 리드문에는 사람들이 검색할 말(`거래 내역`, `카드 명세서`, `소비 분석`)이 들어간다.
- 페이지마다 `metadata`의 title을 `화면 이름 | FinSight`로 준다.
- 시스템 글꼴을 유지한다. 웹폰트, 자동 재생 영상, 슬라이더를 넣지 않는다. 이유: 첫 화면이 늦게 뜨면 방문자가 떠난다.
- 랜딩 title에 서비스가 하는 일을 함께 적고, `/`와 `/sample`에 고유한 description을 준다. [P3]
- 메신저로 공유했을 때 미리보기가 나오도록 Open Graph 제목·설명·이미지를 넣는다. [P3]
- `robots`와 `sitemap`을 추가한다. sitemap에는 `/`와 `/sample`만 넣는다. 파일 규칙은 `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/01-metadata/`를 읽고 따른다. [P3]

## 하지 않는 것
- 사용자가 누르지 않았는데 업그레이드 팝업을 띄우지 않는다. 같은 안내를 닫아도 다시 띄우지 않는다.
- 카운트다운, `오늘만`, 가짜 후기나 가입자 수로 재촉하지 않는다.
- 거절하는 쪽 문구로 죄책감을 주지 않는다 (`아니요, 계속 낭비할게요`).
- 결제 버튼을 누른 뒤에야 금액이 드러나게 하지 않는다. 해지를 가입보다 어렵게 만들지 않는다.
- 권한을 화면에서만 잠그지 않는다 (CLAUDE.md CRITICAL).

구독 결제 화면은 전자상거래법의 온라인 다크패턴 규제(숨은 갱신, 순차공개 가격책정, 취소·탈퇴 방해, 반복간섭 등 6개 유형) 대상이다. Phase 3의 약관 작업에서 결제·해지 흐름을 함께 점검한다.
