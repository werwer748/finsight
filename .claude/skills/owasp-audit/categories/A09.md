# A09 Security Logging and Alerting Failures

출처: https://top10.owasp.org/2025/A09_2025-Security_Logging_and_Alerting_Failures/ · 스냅샷 2026-10-08

## OWASP 요약

로깅과 모니터링이 없으면 공격과 침해를 탐지할 수 없고, 알림이 없으면 사고에 빠르고 효과적으로 대응하기 어렵다.

로그인, 로그인 실패, 고가치 거래 같은 감사 대상 이벤트를 기록하지 않는 것, 경고와 오류가 로그를 남기지 않거나 불명확하게 남기는 것, 로그를 감시하지 않는 것, 알림 기준과 대응 절차가 없는 것, 로그에 민감한 정보가 들어가는 것(CWE-532), 로그 데이터를 인코딩하지 않아 주입에 노출되는 것(CWE-117)이 여기에 든다.

예방은 로그인·접근 제어·서버 측 입력 검증의 실패를 사용자 맥락과 함께 기록하는 것, 보안 통제가 있는 곳은 성공과 실패를 모두 기록하는 것, 로그 관리 도구가 읽기 쉬운 형식으로 남기는 것, 의심스러운 행동에 알림을 내는 것, 사고 대응 계획을 두는 것이다.

## FinSight에서

FinSight의 로그는 Vercel 런타임 로그, Supabase 인증 로그, 공개 PR 댓글로 나가는 리뷰 보고다. 코드로 볼 수 있는 것은 보안 이벤트가 기록되는지와 로그에 민감한 값이 실리는지다. 보존과 알림은 콘솔 설정이라 수동 확인이다.

`P`가 붙은 체크는 OWASP의 CWE-532를 FinSight의 privacy 규칙에 댄 것이다.

## 점검

### A09-1 보안 이벤트의 기록 — 🟡

- 찾기: 서버가 요청을 거부하는 곳(권한 거부, 상한 초과, 파일 거부, 웹훅 서명 실패)과 외부 서비스의 오류를 받는 곳. A01-1, A06-1, A06-2, A08-3, A10-4에서 본 지점을 다시 쓴다.
- 위반: 그 지점에서 아무것도 기록하지 않아, 반복되는 거부나 오류를 나중에 알 수 없다.
- 로그인과 가입의 실패는 Supabase가 기록하므로 앱에 기록이 없어도 통과다. 수동 확인에서 본다.

### A09-P1 로그의 민감한 값 — 시크릿이나 거래 행이면 🔴, 그 밖은 🟠

- 근거: OWASP CWE-532
- 찾기: `grep -rnE "console\.(log|error|warn|info|debug)" src`. 테스트 파일은 뺀다. 결과가 없으면 통과다.
- 위반: 거래 행, 가맹점명, 금액, 파일 이름, 이메일, 토큰, SDK 오류 객체 전체를 로그에 넘긴다.

### A09-2 공개로 나가는 CI 출력의 가림 — 🟡

- 찾기: `scripts/review_gate.py`의 가림 패턴과, `.github/workflows/` 아래의 파일에서 리뷰 job이 받는 `secrets.*`.
- 위반: 리뷰 job에 넘어가는 시크릿 종류 가운데 가림 패턴이 덮지 못하는 것이 있다. 리뷰 보고는 PR 댓글로 공개된다.

## 보고하지 않는다

- 로그 수집 서비스나 오류 수집 서비스가 없는 것. 붙일지는 아직 정하지 않았다.

## 수동 확인

- Vercel → Logs — 현재 플랜의 로그 보존 기간을 알고 있다. 더 길게 필요하면 Log Drain을 건다.
- Supabase → Logs → Auth — 로그인 실패가 보이고 보존 기간을 알고 있다.
- GitHub → Settings → Notifications — `main`의 워크플로 실패가 알림으로 온다.
