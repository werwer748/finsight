# A02 Security Misconfiguration

출처: https://top10.owasp.org/2025/A02_2025-Security_Misconfiguration/ · 스냅샷 2026-10-08

## OWASP 요약

보안 설정 오류는 시스템, 애플리케이션, 클라우드 서비스가 보안 면에서 잘못 설정돼 취약점이 생긴 상태다.

스택 어딘가에 보안 강화가 빠졌거나 클라우드 권한이 잘못 잡힌 것, 필요 없는 기능·계정·권한이 켜진 것, 기본 계정과 비밀번호가 그대로인 것, 오류 처리가 스택 트레이스 같은 지나친 정보를 보여 주는 것, 프레임워크·라이브러리·DB의 보안 설정이 안전한 값이 아닌 것, 서버가 보안 헤더를 보내지 않는 것이 여기에 든다.

예방은 반복할 수 있는 강화 절차, 불필요한 것이 없는 최소 구성, 보안 헤더 전송, 설정의 자동 검증(자동화하지 못하면 적어도 해마다 수동 검증), 코드·설정 파일·파이프라인에 정적 키를 넣지 않는 것이다.

## FinSight에서

`next.config.ts`의 응답 헤더와 위험한 옵션, 공개 GitHub 저장소의 보안 기능, GitHub Actions의 기본 권한을 본다. Supabase와 Vercel 콘솔의 설정은 수동 확인이다.

## 점검

### A02-1 Next 설정 — 헤더는 🟡, 위험한 옵션은 표

- 찾기: `next.config.ts`를 읽는다. `grep -nE "headers\(|Content-Security-Policy|poweredByHeader" next.config.ts src/proxy.ts`
- 위반(헤더): `Content-Security-Policy`(적어도 `frame-ancestors`), `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`가 없다. `poweredByHeader`를 끄지 않았다. 빠진 헤더는 묶어서 한 건으로 적는다.
- 위반(옵션): `productionBrowserSourceMaps: true`, `serverActions.allowedOrigins`의 넓은 와일드카드, 이유 없이 올린 `bodySizeLimit`, `typescript.ignoreBuildErrors`.
- 수정안을 적을 때는 `node_modules/next/dist/docs/01-app/02-guides/content-security-policy.md`와 `node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/`의 `headers.md`, `poweredByHeader.md`, `serverActions.md`를 근거로 한다.

### A02-2 공개 저장소의 secret scanning — 🟠

- 찾기: G1의 `visibility`와 `security_and_analysis`.
- 위반: `visibility`가 `public`인데 `secret_scanning`이나 `secret_scanning_push_protection`이 `disabled`다. 둘 다 꺼져 있어도 한 건으로 적는다.
- 🟠인 이유: 공개 저장소에 에이전트가 자동으로 커밋하므로 시크릿이 한 번 들어가면 바로 공개된다. push protection은 그 전에 막는 장치다.
- 저장소가 비공개면 ⚪다.

### A02-3 GitHub Actions의 권한 — 표

- 찾기: G5와 `.github/workflows/` 아래의 파일.
- 위반: 기본 토큰 권한(`default_workflow_permissions`)이 `write`다. `can_approve_pull_request_reviews`가 true다. `permissions:`가 없는 워크플로가 있다.

## 보고하지 않는다

- `next.config.ts`에 HSTS가 없는 것. 배포 플랫폼이 붙이는지를 수동 확인에서 본다.

## 수동 확인

- 배포 사이트 — `curl -sI https://<운영 도메인>/`의 응답에 `Strict-Transport-Security`가 있고 `X-Powered-By`가 없으며 A02-1의 헤더가 실린다.
- Vercel → Settings → Environment Variables — 시크릿이 Sensitive로 표시돼 있고 `NEXT_PUBLIC_`으로 시작하는 시크릿이 없다.
- Vercel → Settings → Deployment Protection — Preview 배포가 누구에게나 열려 있지 않다.
- Supabase → Authentication → Sign In / Providers — Email만 켜져 있고(ADR-003) 익명 로그인이 꺼져 있다.
