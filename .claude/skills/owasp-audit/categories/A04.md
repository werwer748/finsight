# A04 Cryptographic Failures

출처: https://top10.owasp.org/2025/A04_2025-Cryptographic_Failures/ · 스냅샷 2026-10-08

## OWASP 요약

암호화가 없거나, 충분히 강하지 않거나, 암호 키가 새는 실패를 다룬다. 전송 중인 데이터는 모두 전송 계층에서 암호화해야 한다.

OWASP가 묻는 것은 이런 것이다. 낡거나 약한 알고리즘과 프로토콜을 쓰는가. 기본 키나 약한 키를 쓰거나 키를 돌려 쓰거나 교체하지 않는가. 키가 소스 저장소에 들어 있는가. 암호화를 강제하는 보안 헤더가 빠졌는가. 암호 용도가 아닌 난수를 쓰는가. MD5나 SHA-1 같은 폐기된 해시를 쓰는가.

예방은 처리·저장·전송하는 데이터를 분류해 민감한 것을 식별하는 것, 민감한 데이터를 필요 없이 저장하지 않는 것, 저장과 전송을 암호화하고 HSTS로 HTTPS를 강제하는 것, 민감한 응답을 캐시하지 않는 것, 검증된 구현과 암호용 난수를 쓰는 것, 비밀번호를 솔트가 든 적응형 해시로 저장하는 것이다.

## FinSight에서

FinSight는 암호화를 직접 구현하지 않는다. TLS는 Vercel과 Supabase가, 비밀번호 해시는 Supabase가 맡는다. 그래서 볼 것은 키와 시크릿의 관리, 민감한 응답의 캐시, 민감한 데이터를 필요 이상으로 내보내거나 저장하지 않는가다.

`P`가 붙은 체크는 OWASP의 "데이터를 분류하고 민감한 데이터를 필요 없이 저장하지 않는다"를 FinSight의 privacy 규칙에 댄 것이다.

## 점검

### A04-1 저장소와 이력의 시크릿 — 🔴

- 찾기: L5, L6, L7, G6, `grep -nE '=.+' .env.example`
- 위반:
  - env 파일이 이력에 들어간 적이 있다.
  - 이력에 시크릿 모양의 문자열이 있다.
  - `.env.local`이 무시되지 않는다.
  - `.env.example`에 실제 값이 들어 있다.
  - GitHub에 열려 있는 secret scanning 알림이 있다.
- 값은 적지 않는다. 종류와 위치(커밋, 경로)만 적는다.

### A04-2 클라이언트로 나가는 시크릿 — 🔴

- 근거: CLAUDE.md CRITICAL(서버 전용 호출)
- 찾기: I8과 L8.
- 위반: Supabase URL과 publishable key가 아닌 `NEXT_PUBLIC_` 이름이 있다. I3에서 닿을 수 있는 모듈이 서버 전용 환경변수를 읽는다. L8에 결과가 나온다.

### A04-3 직접 쓰는 암호 기능 — 표

- 찾기: `grep -rnE "node:crypto|createHash|createHmac|Math\.random|md5|sha1" src`. 결과가 없으면 ⚪다.
- 위반: 토큰이나 식별자를 `Math.random`으로 만든다. 보안 용도에 MD5나 SHA-1을 쓴다. 서명을 `===`로 비교한다.

### A04-4 민감한 응답의 캐시 — 🟠 (다른 사용자에게 보이면 🔴)

- 찾기: `grep -rnE "[\"']use cache[\"']|unstable_cache|export const revalidate|force-static|cacheComponents" src next.config.ts`. 사용자 데이터를 읽는 I1의 페이지와 핸들러도 본다.
- 위반: 사용자 데이터가 캐시되는 범위나 정적으로 만들어지는 페이지 안에 있다.

### A04-P1 LLM으로 나가는 데이터 — 🔴

- 근거: CLAUDE.md CRITICAL(LLM 전송), ADR-004, ADR-012
- 찾기: I5에서 `@anthropic-ai/sdk`를 import하는 파일과 그 호출부. 없으면 ⚪다.
- 위반: 가맹점명과 집계된 통계가 아닌 값이 호출에 들어간다. ADR-012가 보내지 않기로 한 행의 내용이 캐시 조회나 Claude 호출로 넘어간다. 보내기 전에 ADR-012의 가림을 하지 않는다.

### A04-P2 필요 이상으로 저장하는 데이터 — 🟠

- 근거: ADR-014
- 찾기: I4의 테이블 컬럼과 insert에 넣는 값. 없으면 ⚪다.
- 위반: ADR-014가 꺼내지도 저장하지도 않기로 한 값을 저장한다.

## 보고하지 않는다

- Supabase URL과 publishable key가 `NEXT_PUBLIC_`으로 클라이언트에 나가는 것. 공개하도록 만든 값이다.
- 테스트 픽스처와 `scripts/review_gate.py`의 가림 패턴에 있는 시크릿 모양의 문자열.
- `.env.local`이 있다는 것. 무시되고 있고 이력에 없으면 문제가 아니다.

## 수동 확인

- 배포 사이트 — `http://`로 열면 `https://`로 넘어가고 `Strict-Transport-Security`가 실린다.
- Supabase → Project Settings → API Keys와 JWT Keys — 키를 누가 갖고 있고 언제 바꿨는지 안다.
- Anthropic Console → API keys — 키가 FinSight 전용 워크스페이스에 묶여 있다.
