# A05 Injection

출처: https://top10.owasp.org/2025/A05_2025-Injection/ · 스냅샷 2026-10-08

## OWASP 요약

주입 취약점은 신뢰할 수 없는 사용자 입력이 해석기(브라우저, 데이터베이스, 명령줄)로 넘어가 그 일부가 명령으로 실행되는 결함이다. SQL 주입(CWE-89), 크로스 사이트 스크립팅(CWE-79), OS 명령 주입(CWE-78)이 대표적이다.

사용자가 준 데이터를 검증하거나 걸러내지 않는 것, 동적 쿼리나 매개변수화하지 않은 호출을 해석기에 그대로 쓰는 것, 적대적일 수 있는 데이터를 쿼리나 명령에 이어 붙이는 것이 여기에 든다.

예방은 해석기를 거치지 않거나 매개변수화된 인터페이스를 주는 안전한 API를 쓰는 것, 서버에서 허용 목록 방식으로 입력을 검증하는 것, 남은 동적 쿼리는 그 해석기의 문법으로 특수 문자를 이스케이프하는 것이다.

## FinSight에서

FinSight의 입력은 폼 값, 쿼리 문자열, 사용자가 올린 파일의 셀 문자열이다. 파일에서 나온 가맹점 문자열은 DB 쿼리, 화면, Claude 프롬프트로 흘러간다. 그 값이 각 해석기에 명령으로 읽히는가를 본다.

## 점검

### A05-1 서버의 입력 검증 — 표

- 찾기: I1과 I2의 파일에서 `grep -nE "searchParams|formData|headers\(\)|request\.json\(\)| as [A-Z]"`
- 위반: 외부 입력을 검증 없이 쓴다. 허용 목록으로 좁히지 않고 타입 단언(`as`)으로 좁힌다.

### A05-2 DB 쿼리 조립 — 🟠

- 찾기: I4의 파일에서 `grep -nE '\.or\(|\.filter\(|\.rpc\(|\$\{'`. SQL 파일의 동적 SQL(`execute`, `format(`)은 Read로 본다. 대상이 없으면 ⚪다.
- 위반: 사용자나 파일에서 온 값을 필터 문자열이나 SQL에 이어 붙인다.

### A05-3 위험한 싱크 — 표

- 찾기: `grep -rnE "dangerouslySetInnerHTML|innerHTML|child_process|node:fs|href=\{" src`. 결과마다 사용자나 파일의 데이터가 닿는지 호출부까지 읽고 판단한다.
- 위반: 사용자나 파일의 데이터가 HTML, 셸 명령, 파일 경로, `href`로 검증 없이 들어간다.

### A05-4 LLM 출력의 신뢰 — 🟠

- 근거: ADR-004 (LLM은 가맹점 분류와 문장 작성만 맡는다)
- 찾기: I5에서 `@anthropic-ai/sdk`를 import하는 파일과 그 출력을 받는 곳. 없으면 ⚪다.
- 위반: LLM 출력을 쿼리, URL, HTML, 권한 판단에 쓴다. 카테고리를 허용 목록 없이 받아 저장한다. 프롬프트가 파일에서 온 문자열을 지시와 구분하지 않는다.

## 보고하지 않는다

- 값을 상수와 비교만 하는 쿼리 문자열. 해석기로 넘어가지 않는다.
- 문자열 리터럴만 넘기는 `redirect()`.
