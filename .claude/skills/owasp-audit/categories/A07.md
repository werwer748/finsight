# A07 Authentication Failures

출처: https://top10.owasp.org/2025/A07_2025-Authentication_Failures/ · 스냅샷 2026-10-08

## OWASP 요약

공격자가 시스템을 속여 유효하지 않은 사용자를 정당한 사용자로 인식하게 만들 수 있으면 이 취약점이 있다.

크리덴셜 스터핑이나 무차별 대입 같은 자동화 공격을 빨리 막지 못하는 것, 기본·약한·유출된 비밀번호를 허용하는 것, 약한 비밀번호 복구 절차, 다중 인증이 없거나 효과가 없는 것, 세션 식별자를 URL에 드러내는 것, 로그인 뒤에도 같은 세션 식별자를 쓰는 것, 로그아웃이나 비활성 뒤에 세션을 무효화하지 않는 것이 여기에 든다.

예방은 다중 인증, 약한 비밀번호와 유출된 비밀번호의 검사, NIST 800-63b에 맞춘 비밀번호 정책, 모든 결과에 같은 메시지를 써서 계정 열거를 막는 것, 로그인 실패의 제한과 기록, 서버 측 세션 관리(로그인 뒤 새 식별자, 안전한 쿠키, 로그아웃과 만료 때 무효화), 검증된 인증 시스템에 맡기는 것, JWT의 `aud`와 `iss` 검증이다.

## FinSight에서

인증은 Supabase Auth가 맡는다(ADR-002, ADR-003). 앱이 책임지는 것은 세션을 검증된 방법으로 읽는지, 세션 쿠키의 속성, 가입과 로그인의 응답이 계정 존재를 드러내는지다. 비밀번호 정책, 시도 제한, 메일 확인은 콘솔 설정이라 수동 확인이다.

## 점검

### A07-1 검증된 세션 읽기와 로그아웃 — 🟠

- 근거: ADR-002
- 찾기: `grep -rnE "getSession\(|getUser\(|getClaims\(|jwtDecode|decodeJwt" src`
- 위반: 서버의 판단에 `getSession()`이나 검증 없이 풀어 본 쿠키 값을 쓴다. 로그아웃이 GET으로 열려 있다. 로그아웃이 Supabase 세션을 지우지 않는다.
- `getClaims()`와 `getUser()`는 토큰을 검증하므로 통과다.

### A07-2 세션 쿠키 속성 — 🟡

- 찾기: `grep -rnE "createServerClient\(|cookieOptions" src`. 기본값은 `node_modules/@supabase/ssr/dist/main/utils/constants.js`에서 읽는다.
- 위반: 브라우저에서 세션을 읽는 코드가 없는데 쿠키가 라이브러리 기본값 그대로이고 그 기본값에서 `httpOnly`가 꺼져 있다. `secure`나 `sameSite`가 약하다.
- 수정안을 적을 때는 설치된 `@supabase/ssr`가 `cookieOptions`로 그 값을 받는지 확인한다. 확인하지 못했으면 그렇게 적는다.

### A07-3 계정 열거 — 🟡 (설정과 무관하게 항상 드러나면 🟠)

- 찾기: 인증 오류를 문구로 바꾸는 곳과 I2의 가입·로그인 액션이 돌려주는 값을 읽는다.
- 위반: 가입이나 로그인의 응답이 그 이메일의 가입 여부에 따라 달라진다.

### A07-4 서버의 비밀번호 규칙 — 표

- 근거: ADR-003
- 찾기: I2의 가입·로그인 액션과 그 액션이 부르는 검증 함수.
- 위반: 비밀번호 검증이 클라이언트에만 있다. 비밀번호를 응답, 로그, 오류 메시지에 싣는다.

## 보고하지 않는다

- 다중 인증, 비밀번호 재설정 화면, 소셜 로그인이 없는 것. ADR-003이 로그인 수단을 이메일과 비밀번호 하나로 정했다.
- 앱 코드에 로그인 시도 제한이 없는 것. Supabase가 맡고 수동 확인에서 본다.
- `getClaims()`를 검증 없는 세션 읽기로 보는 것.

## 수동 확인

- Supabase → Authentication → Sign In / Providers → Email — Confirm email이 켜져 있다(ADR-003). 꺼져 있으면 A07-3의 응답 차이가 실제로 드러난다. 최소 비밀번호 길이가 앱의 검증과 같고, 유출된 비밀번호 차단을 쓸 수 있으면 켜져 있다.
- Supabase → Authentication → Rate Limits — 로그인, 가입, 메일 발송의 한도가 걸려 있다.
- Supabase → Authentication → Sessions — 세션 만료와 비활성 만료가 정해져 있다.
- Supabase → Authentication → Emails → SMTP Settings — 출시 전에 자체 SMTP를 연결한다(ADR-002).
- Vercel, Supabase, Polar, Anthropic 콘솔 계정 — 2단계 인증이 켜져 있다.
