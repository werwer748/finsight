# A03 Software Supply Chain Failures

출처: https://top10.owasp.org/2025/A03_2025-Software_Supply_Chain_Failures/ · 스냅샷 2026-10-08

## OWASP 요약

소프트웨어 공급망 실패는 소프트웨어를 빌드하고 배포하고 갱신하는 과정의 고장이나 침해다. 시스템이 기대는 서드파티 코드, 도구, 의존성의 취약점이나 악의적 변경에서 비롯되는 경우가 많다. 2013년판의 "알려진 취약점이 있는 컴포넌트 사용"에서 시작해 공급망 전체로 범위가 넓어졌다.

쓰는 컴포넌트의 버전을 추적하지 않는 것, 취약하거나 지원이 끝났거나 낡은 소프트웨어, 정기적으로 스캔하지 않는 것, 공급망의 변경을 추적하지 않는 것, 신뢰할 수 없는 출처의 컴포넌트, 자신이 빌드하고 배포하는 시스템보다 보안이 약한 CI/CD가 여기에 든다.

예방은 직접 의존성과 전이 의존성의 추적, 쓰지 않는 의존성 제거, CVE·NVD·OSV 같은 출처의 지속 감시, 공식 출처에서 안전한 연결로만 받기, 버전을 의도해서 고르기, 그리고 저장소(시크릿을 넣지 않기, 브랜치 보호)·개발 장비·CI/CD·산출물의 강화다.

## FinSight에서

npm 패키지, GitHub 액션, CI가 설치하는 도구가 알려진 취약점 없이, 정해진 출처에서, 고정된 버전으로 들어오는가를 본다. 대상은 lockfile, `npm audit`, ADR-013의 SheetJS CDN tarball, 시크릿을 쥔 CI job이 내려받는 것들이다.

A08과는 이렇게 나눈다. A03은 가져다 쓰는 것이고, A08은 들여보내는 것이다.

## 점검

### A03-1 알려진 취약점 — 운영 의존성은 🟠, 개발 전용은 🟡

- 찾기: L1과 L2.
- 판정:
  - L2에 high 이상이 있으면 🟠, 그 아래만 있으면 🟡다.
  - 취약한 코드에 사용자 입력이 닿아 데이터가 드러나는 호출 지점을 댈 수 있을 때만 🔴다.
  - L1에만 있고 L2에 없으면 개발 전용이므로 🟡다.
- 근본 advisory 하나를 한 건으로 적는다. 영향받는 패키지마다 따로 세지 않는다.
- 수정안에 `npm audit fix --force`를 적지 않는다. 제안된 수정이 메이저 버전 변경이나 다운그레이드면 그 사실을 적는다.

### A03-2 lockfile의 출처와 무결성 — 🟠

- 찾기: L3, L4, `ls .npmrc`, `git ls-files package-lock.json`
- 위반:
  - `package-lock.json`이 없거나 git에 들어 있지 않다.
  - `resolved`가 `https://registry.npmjs.org/` 밖을 가리킨다. ADR-013의 SheetJS URL은 예외다.
  - `integrity`가 없는 항목이 있다. L4의 두 수가 다르면 그 항목을 찾는다.
  - L3이 서명이 틀리거나 없는 패키지를 보고한다.
  - `.npmrc`가 레지스트리를 바꾼다.

### A03-3 SheetJS 고정 — 🟠

- 근거: ADR-013
- 찾기: `grep -n '"xlsx"' package.json`. 없으면 ⚪다.
- 위반: ADR-013이 적은 URL과 버전이 아니다. npm 레지스트리에서 설치했다. lockfile의 해당 항목에 `integrity`가 없다.

### A03-4 지속 감시 — 🟡

- 찾기: G4, `ls .github/dependabot.yml`
- 위반: Dependabot 알림이 꺼져 있다.

### A03-5 CI가 내려받는 것의 고정 — 🟡

- 찾기: `.github/workflows/` 아래의 파일을 읽는다. G5의 `sha_pinning_required`.
- 위반: `uses:`가 커밋 SHA가 아니라 태그를 가리킨다. `npm install -g`나 `npx`에 버전이 없다. `curl | sh`로 설치한다.
- 태그로 가리킨 액션은 묶어서 한 건으로 적고 줄 번호를 모두 단다. 버전 없는 설치는 따로 한 건이다.
- 시크릿이나 쓰기 토큰을 쥔 job이 GitHub 공식(`actions/*`)이 아닌 액션을 태그로 가리키면 🟠다.

## 보고하지 않는다

- 최신 버전이 아니라는 것만으로는 보고하지 않는다. 낡은 것과 취약한 것은 다르다.
- SBOM 파일이 없는 것. 이 규모에서는 lockfile이 목록이다.

## 수동 확인

- https://cdn.sheetjs.com/ — 고정한 버전보다 새 릴리스가 있는지 본다. ADR-013은 `npm audit`와 자동 업데이트 도구가 새 버전을 알려 주지 않는다고 적는다. `xlsx`를 설치한 뒤부터 본다.
- Vercel → Settings → General → Node.js Version — 지원 중인 LTS다.
- GitHub → Settings → Password and authentication — 저장소에 push할 수 있는 계정에 2단계 인증이 켜져 있다.
