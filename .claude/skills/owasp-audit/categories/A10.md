# A10 Mishandling of Exceptional Conditions

출처: https://top10.owasp.org/2025/A10_2025-Mishandling_of_Exceptional_Conditions/ · 스냅샷 2026-10-08

## OWASP 요약

2025판에 새로 생긴 항목이다. 프로그램이 드물고 예측하기 어려운 상황을 막지 못하거나, 알아채지 못하거나, 제대로 대응하지 못할 때 생긴다. 잘못된 오류 처리, 논리 오류, 열린 채로 실패하는 것(failing open)에 초점을 둔다.

원인은 빠지거나 부족한 입력 검증, 오류가 난 자리가 아니라 뒤늦게 높은 수준에서 하는 처리, 메모리·권한·네트워크 같은 환경의 예상 밖 상태, 처리하지 않은 예외다. 결과로 논리 버그, 경쟁 상태, 부정 거래, 인증과 권한의 문제가 생긴다.

예방은 오류를 난 자리에서 잡아 의미 있게 처리하는 것(사용자에게 이해할 수 있게 알리고, 기록하고, 필요하면 알림), 놓친 것을 받는 전역 예외 처리기, 거래 도중에 실패하면 전부 되돌리고 다시 시작하는 것(fail closed), 속도 제한과 자원 할당량 같은 한도, 엄격한 입력 검증, 한 곳에서 같은 방식으로 하는 오류 처리다.

## FinSight에서

FinSight의 예외 상황은 세션 확인 실패, 환경변수 누락, Supabase와 Claude의 오류, 업로드의 중간 실패다. 실패했을 때 접근을 허용하거나, 상한을 풀거나, 내부 정보를 보여 주면 발견이다.

## 점검

### A10-1 닫힌 채로 실패 — 데이터나 권한이 열리면 🔴, 아니면 🟠

- 찾기: A01-1, A01-5, A06-1, A08-3에서 본 판단 지점마다, 조회가 오류를 내거나 `null`을 돌려줄 때 어떻게 되는지 읽는다.
- 위반: 세션, 권한, 상한, 서명의 확인이 실패했을 때 통과시킨다.

### A10-2 빠진 값 — 표

- 찾기: I1과 I2의 파일에서 `.get(`의 결과, `as` 단언, `!` 단언이 템플릿 문자열이나 호출로 들어가는 곳.
- 위반: 없을 수 있는 값(`null`인 헤더, 빠진 쿼리 값)을 확인 없이 쓴다.

### A10-3 오류가 드러내는 내부 정보 — 표

- 찾기: `grep -rnE "error\.message|\.stack|String\(e" src`와 `find src/app -name 'error.tsx' -o -name 'global-error.tsx'`
- 위반: 응답이나 화면에 외부 서비스의 오류 메시지, 스택, 쿼리, 키가 실린다.

### A10-4 외부 호출의 실패와 중간 실패 — 🟠

- 근거: ADR-004(분류하지 못한 가맹점의 처리), ADR-014(다시 올릴 때의 중복 판정)
- 찾기: Supabase와 서비스 호출을 `await`하는 곳에서 `error`를 확인하는지 읽는다.
- 위반: 실패를 성공으로 보여 준다. 여러 단계로 쓰다가 중간에 실패한 상태가 남고, 다시 시도해도 안전하지 않다.

## 보고하지 않는다

- `error.tsx`가 없는 것. Next의 운영 빌드 기본 오류 화면은 내부 정보를 보여 주지 않는다.
- 서버 컴포넌트에서 쿠키를 쓰려다 나는 예외를 무시하는 `catch` (`src/lib/supabase/server.ts`). 세션 갱신은 proxy가 맡는다.
- 환경변수가 없을 때 로그인하지 않은 것으로 처리하는 것. 보호 경로는 로그인으로 넘어가므로 닫힌 채 실패한다.

## 수동 확인

- 배포 사이트 — 깨진 확인 링크(`/auth/confirm?code=x`)와 없는 주소를 열었을 때 한국어 안내만 나오고 스택이나 내부 경로가 보이지 않는다.
