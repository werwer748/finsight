# A06 Insecure Design

출처: https://top10.owasp.org/2025/A06_2025-Insecure_Design/ · 스냅샷 2026-10-08

## OWASP 요약

안전하지 않은 설계는 "통제 설계가 없거나 효과가 없는 것"이다. 설계 결함과 구현 결함은 원인도 고치는 방법도 다르다. 안전한 설계에도 구현 결함은 생길 수 있지만, 필요한 통제를 애초에 만들지 않은 설계는 구현이 완벽해도 고쳐지지 않는다.

대표 약점은 위험한 형식의 파일을 제한 없이 올릴 수 있는 것(CWE-434), 신뢰 경계 위반(CWE-501), 부적절한 권한 관리(CWE-269), 보호되지 않은 자격 증명 저장(CWE-256, CWE-522)이다.

예방은 인증, 접근 제어, 비즈니스 로직, 주요 흐름의 위협 모델링, 계층마다 두는 타당성 검사, 주요 흐름이 위협 모델에 견디는지 확인하는 단위·통합 테스트(정상 사용과 오용 사례), 테넌트를 설계 단계에서 분리하는 것이다.

## FinSight에서

FinSight가 설계로 정해 둔 통제는 업로드 남용 상한(ADR-011)과 업로드 파일 방어(ADR-013)다. 이 통제가 설계대로 서버에 있는지, 로그인 없는 경로가 비용을 일으키지 않는지, 방어가 테스트로 고정돼 있는지를 본다.

## 점검

### A06-1 업로드 상한과 미래 날짜 거부 — 🟠

- 근거: ADR-011
- 찾기: I6의 업로드 핸들러. 없으면 ⚪다.
- 위반: ADR-011의 사용자별 업로드 상한이 서버에 없다. 상한을 파일을 처리한 뒤에 확인한다. 미래 날짜가 든 업로드를 저장한다.

### A06-2 업로드 파일 방어 — 🟠

- 근거: ADR-013
- 찾기: I6에서 `xlsx`를 import하는 파일과 그 앞 단계. 없으면 ⚪다.
- 위반: ADR-013의 "결정"에 적힌 방어를 하나씩 대조해 빠진 것이 있다. 방어가 SheetJS에 파일을 넘긴 뒤에 실행된다.

### A06-3 로그인 없는 경로의 비용과 쓰기 — 🟠

- 근거: ADR-011의 이유(업로드 한 번이 Claude 요청을 여러 건 일으킨다)
- 찾기: I1 가운데 보호 경로 밖의 페이지와 핸들러. `@/services/*`를 import하거나 DB에 쓰는지 본다.
- 위반: 로그인하지 않은 요청이 Claude 호출이나 DB 쓰기를 일으킨다.

### A06-4 방어를 고정하는 테스트 — 🟡

- 찾기: 방어 코드 옆의 `*.test.*` 파일.
- 위반: 방어의 실패 케이스를 확인하는 테스트가 없다. 지금 대상은 보호 경로의 리다이렉트와 검증된 세션 읽기다. 코드가 생긴 뒤에는 ADR-011, ADR-012, ADR-013의 한도와 "요청이 보낸 사용자 ID를 믿지 않는다"가 더해진다.

## 보고하지 않는다

- 위협 모델 문서나 보안 전담 인력이 없는 것.
- ADR이 받아들인 트레이드오프. 예를 들어 ADR-003은 비밀번호 재설정 화면을 MVP에서 뺐다.
