# A08 Software or Data Integrity Failures

출처: https://top10.owasp.org/2025/A08_2025-Software_or_Data_Integrity_Failures/ · 스냅샷 2026-10-08

## OWASP 요약

유효하지 않거나 신뢰할 수 없는 코드와 데이터가 신뢰할 수 있는 것으로 취급되는 것을 막지 못하는 코드와 인프라의 문제다. 공급망 실패(A03)보다 낮은 수준에서, 신뢰 경계를 지키고 소프트웨어·코드·데이터의 무결성을 확인하는 데 초점을 둔다.

신뢰할 수 없는 출처나 CDN의 플러그인·라이브러리에 기대는 것, 무결성 확인이 없는 CI/CD 파이프라인, 서명을 확인하지 않고 받아 쓰는 코드와 산출물, 검증 없이 적용하는 자동 업데이트, 공격자가 보고 고칠 수 있는 직렬화 데이터를 그대로 믿는 것이 여기에 든다.

예방은 디지털 서명 같은 방법으로 출처와 무변조를 확인하는 것, 신뢰하는 저장소의 의존성만 쓰는 것, 코드와 설정 변경의 리뷰 절차, CI/CD의 분리·설정·접근 제어, 신뢰할 수 없는 쪽에서 온 직렬화 데이터를 무결성 확인 없이 쓰지 않는 것이다.

## FinSight에서

`main`에 들어가는 변경이 리뷰와 테스트 관문을 거치는가, 바깥에서 온 데이터(Polar 웹훅)를 확인 없이 믿는가를 본다.

A03과는 이렇게 나눈다. A03은 가져다 쓰는 것이고, A08은 들여보내는 것이다.

## 점검

### A08-1 `main` 보호 — 보호가 없거나 force push를 허용하면 🟠, 그 밖은 🟡

- 찾기: G2, G3. 워크플로의 job 이름은 `.github/workflows/` 아래의 파일에서 읽는다.
- 위반(🟠): `main`에 보호 규칙도 ruleset도 없다. force push나 삭제를 허용한다.
- 위반(🟡): 필수 체크에 리뷰 job이나 테스트 job이 빠져 있다. `enforce_admins`가 꺼져 있다. 묶어서 한 건으로 적는다.

### A08-2 CI 관문의 자기 보호 — 표

- 찾기: `.github/workflows/` 아래의 파일, `.githooks/pre-commit`, `scripts/review_gate.py`를 읽는다.
- 위반:
  - `pull_request_target`이나 `workflow_run`에서 PR의 코드를 체크아웃해 실행한다.
  - 포크 PR에 시크릿이 넘어간다.
  - `run:` 안에 `${{ github.event.* }}`의 문자열 값을 직접 끼운다.
  - LLM을 돌리는 step에 GitHub 토큰이 환경변수나 체크아웃 자격 증명으로 넘어간다.
  - LLM을 돌리는 job에 `contents: write`가 있다.
  - 자동 머지의 `PROTECTED` 경로 검사나 `--match-head-commit`이 없어졌다.
  - CI에서 리뷰를 건너뛰는 환경변수를 세운다.

### A08-3 웹훅 서명 검증 — 권한이나 플랜이 바뀌면 🔴, 아니면 🟠

- 근거: CLAUDE.md CRITICAL(권한 체크)
- 찾기: I7의 웹훅 핸들러. 없으면 ⚪다.
- 위반: 서명을 검증하지 않는다. 원본 본문이 아니라 파싱한 값으로 검증한다. 검증하기 전에 본문을 읽어 동작한다.

### A08-4 외부 스크립트와 리소스 — 표

- 찾기: `grep -rnE "next/script|<script|<iframe|<link[^>]+https?://" src`. 결과가 없으면 통과다.
- 위반: 서드파티 스크립트를 버전 고정이나 `integrity` 없이 불러온다.

## 보고하지 않는다

- PR 승인이 필수가 아닌 것. 혼자 운영하는 저장소에서는 자기 PR을 승인할 수 없다.
- `run:` 안의 PR 번호 같은 숫자 값.
- `scripts/execute.py`가 Codex를 샌드박스 없이 실행하는 것. `scripts/AGENTS.md`에 적힌 결정이다.
- "금액은 코드로 계산한다" 규칙의 위반. 정확성 규칙이고 `/review-code`의 correctness가 본다.

## 수동 확인

- Vercel → Settings → Git — Production Branch가 `main`이고 쓰지 않는 Deploy Hook이 없다.
- Polar → Webhooks — 엔드포인트가 운영 주소이고 시크릿이 Vercel 환경변수와 같다. Phase 2부터 본다.
