# 리뷰어 공통 규칙

`/review-code`가 띄운 모든 리뷰어가 따른다. 차원별 체크리스트는 `layers/<차원>.md`에 있다.

## 범위

- 맡은 차원만 본다. 다른 차원의 문제는 보여도 보고하지 않는다. 그 차원의 리뷰어가 본다.
- 변경된 줄과, 그 변경 때문에 깨지는 곳만 지적한다. 이번 변경과 무관한 기존 코드의 문제는 보고하지 않는다.

## 읽는 법

- 프롬프트로 merge-base와 변경 파일 목록을 받는다.
- 변경 내용은 `git diff <merge-base> -- <파일>`로 본다. 맥락이 필요하면 Read로 파일 전체와 호출부를 읽는다.
- 추적되지 않는 새 파일은 diff에 나오지 않는다. Read로 전체를 읽는다.
- 삭제된 파일(`D`)은 Read할 수 없다. 필요하면 `git show <merge-base>:<경로>`로 본다.
- 생성 파일(`package-lock.json`)과 바이너리(`.ico`, 이미지)는 읽지 않는다. 의존성 변경은 `package.json`의 diff로 본다.
- 변경 파일 목록에서 맡은 차원과 관계있는 파일만 골라 읽는다. 전부 읽지 않는다.
- 체크리스트의 "읽을 문서"는 적힌 절만 읽는다. 문서 전체를 읽지 않는다.
- Bash는 읽기 전용 명령에만 쓴다: `git diff`, `git log`, `git show`와 검색(`grep`, `rg`, `find`, `ls`).
- `scripts/bash_guard.py`가 `DROP TABLE` 같은 문자열이 든 Bash 명령을 막는다. 검색이 막히면 Read로 파일을 직접 읽는다.

## 하지 않는 것

- 파일을 고치지 않는다.
- `npm` 명령(lint, build, test, install)을 실행하지 않는다. 정적 리뷰만 한다.

## 발견 사항

발견마다 아래를 모두 적는다. 근거를 댈 수 없으면 보고하지 않는다.

- 위치: `파일:줄`. 파일은 저장소 루트 기준 상대 경로로 적는다.
- 코드: 해당 줄 인용
- 이유: 왜 문제인가. 근거가 된 규칙이나 문서
- 수정: 구체적인 수정 방안

발견마다 위험 단계를 하나 매긴다.

| 단계 | 뜻 | 해당하는 것 |
|---|---|---|
| 🔴 위험 | 머지 금지 | CLAUDE.md CRITICAL 규칙 위반, 데이터·시크릿 노출, 금액이 틀리는 버그 |
| 🟠 경고 | 머지 전 수정 | 재현되는 버그, 빠진 검증, 명세·ADR과 다른 동작 |
| 🟡 주의 | 수정 권장 | 빠진 테스트, 구조 이탈, 비효율, 네이밍·문구 같은 사소한 개선 |

CRITICAL 규칙 위반은 항상 🔴다. 그 밖에 두 단계 사이에서 망설여지면 낮은 쪽을 고르고 불확실한 점을 이유에 적는다.

## 보고 형식

마지막 메시지가 그대로 `/review-code`에 전달된다. 인사말이나 과정 설명 없이 보고만 쓴다. 맡은 차원마다 아래 한 덩어리를 쓴다.

```
## <차원>: 발견 N건

1. 🔴 위험 — <제목>
   위치: `파일:줄`
   코드: <해당 줄 인용>
   이유: <왜 문제인가>
   수정: <수정 방안>
2. 🟡 주의 — <제목>
   …
```

발견이 없으면 제목 줄만 쓴다.

- `## <차원>: 양호` — 살펴봤는데 발견이 없다.
- `## <차원>: 해당 없음` — 변경에 이 차원이 볼 것이 없다. 이유를 한 줄 덧붙인다.
