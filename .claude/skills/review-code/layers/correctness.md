# correctness — 로직·버그

코드가 하려는 일을 실제로 맞게 하는지 본다.

## 본다

- 변경된 로직의 오류: 조건 반전, 경계값(빈 입력, 0, 음수, 하나뿐인 항목), 하나 차이 오류, null·undefined, 잘못된 비교.
- 비동기 처리: 빠진 `await`, 처리되지 않은 오류, 실패했는데 성공으로 이어지는 흐름.
- 금액과 날짜 계산, 파싱과 정규화.

## 보지 않는다

- 명세에 적힌 요구사항이 빠졌는지 → behavioral
- 테스트가 있는지, 빠진 케이스가 있는지 → test-coverage
- 인증과 권한 → security
- 느린 코드 → performance, cpu-perf

## 읽을 문서

- `CLAUDE.md`의 CRITICAL 중 금액 계산 규칙 (이미 컨텍스트에 있다)
- `docs/ADR.md`에서 변경이 닿는 것만: ADR-004(분류와 캐시), ADR-011(조회 기간, 업로드 상한), ADR-012(은행 내역 분류), ADR-014(중복 지문), ADR-015(이체와 취소)

## 체크 항목

1. 금액 합계와 통계를 코드로 계산하는가? LLM 출력에서 숫자를 가져오면 🔴다.
2. 금액 계산에 부동소수 오차나 부호 뒤바뀜(지출, 수입, 취소)이 없는가?
3. 조회 기간이 ADR-011과 같은가? 끝은 저장된 최근 거래일, 시작은 그 한 달 전 다음 날이고, 오늘 날짜를 기준으로 쓰지 않는다. 미래 날짜가 든 업로드는 거부한다.
4. `이체`가 총 지출과 카테고리 집계에서 빠지는가? 은행 내역에 입금으로 찍힌 카드 결제 취소가 음수 지출로 처리되는가? (ADR-015)
5. 은행 내역의 분류가 ADR-012와 같은가? 입금은 `수입`, 카드 결제로 확인되지 않은 출금은 `이체`이고, 확인 기준은 거래구분의 `체크`뿐이다.
6. 중복 지문이 ADR-014의 구성(날짜, 시각, 내용, 금액, 종류, 같은 파일 안에서 앞에 나온 횟수)과 같은가?
7. 분류하지 못한 가맹점이 캐시에 남지 않고 `기타`로 저장되는가? (ADR-004)
8. 날짜와 문자열 파싱이 시간대, 형식 차이, 빈 칸에서 깨지지 않는가?
9. 오류 경로에서 상태가 반쯤 바뀐 채 남지 않는가?
