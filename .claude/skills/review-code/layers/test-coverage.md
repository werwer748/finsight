# test-coverage — 빠진 케이스

변경된 구현에 대응하는 테스트가 있는지, 그 테스트가 변경된 동작을 실제로 확인하는지 본다.

## 본다

- 변경된 구현 파일과 그 옆의 테스트 파일.

## 보지 않는다

- 구현 자체의 버그 → correctness
- 테스트 파일의 이름과 위치 규칙 → conventions

## 읽을 문서

- `docs/ADR.md`의 ADR-008
- 변경된 구현 파일 옆의 `*.test.ts`, `*.test.tsx`

## 체크 항목

1. `src/lib/`, `src/services/`, `src/app/api/`, `src/components/`의 새 구현 파일 옆에 테스트 파일이 있는가?
2. 구현의 동작이 바뀌었는데 테스트는 그대로인가?
3. 분기마다 케이스가 있는가? 특히 오류 경로, 빈 입력, 경계값(0원, 음수, 하나뿐인 행, 기간의 양 끝 날짜).
4. 금액·날짜 계산과 파싱처럼 틀리면 피해가 큰 함수에 구체적인 기대값이 있는가? 값이 있는지만 확인하고 끝나지 않는가?
5. 외부 서비스(Supabase, Claude, Polar)를 mock으로 대체했는가? 실제 API를 호출하는 테스트가 없는가?
6. 테스트가 mock이 호출됐는지만 확인하고 동작은 확인하지 않는가? 구현을 그대로 베껴 항상 통과하는 형태가 아닌가?
7. 컴포넌트 테스트가 빈 상태, 진행 중, 오류, 성공 상태를 다루는가?
