# cpu-perf — 핫패스·비효율 알고리즘

프로세스 안에서 도는 계산의 비용을 본다. 거래 행 수와 파일 크기에 따라 커지는 코드가 대상이다.

## 본다

- 파싱, 정규화, 분류, 집계처럼 행마다 도는 코드와 렌더링마다 도는 코드.

## 보지 않는다

- 쿼리, 네트워크, 외부 API 호출 → performance

## 읽을 문서

- `docs/ADR.md`의 ADR-013(파일 크기와 시트 수 제한, 메모리): 파싱 코드가 바뀌었을 때만

## 체크 항목

1. 행 수에 대해 제곱으로 커지는 코드가 있는가? 반복문 안의 `find`·`filter`·`includes`·`indexOf`, 중첩 반복.
2. 반복문 안에서 배열이나 객체를 매번 복사하는가? (`reduce` 안의 `[...acc, x]`, `{...acc}`)
3. 같은 값을 반복해서 다시 계산하는가? 반복문 안의 정규식 생성, 날짜 파싱, 정렬.
4. 큰 파일을 통째로 여러 번 메모리에 올리거나 문자열로 바꾸는가? ADR-013의 크기 확인보다 먼저 전체를 읽는가?
5. 클라이언트 컴포넌트가 렌더링마다 무거운 계산을 다시 하는가? 서버에서 한 번 계산해 넘길 수 있는가?
6. 입력 크기에 상한이 없는 반복이나 재귀가 있는가? 길이 제한 없는 입력에 역추적이 심한 정규식을 쓰는가?

행 수가 수백 건인 현재 규모에서 차이가 나지 않는 미세 최적화는 보고하지 않는다.
