# behavioral — 의도 vs 실제 동작

만들려던 것과 만들어진 것이 같은지 본다. 의도는 step 명세, PRD, 커밋 메시지에 적혀 있다.

## 본다

- 명세가 요구한 것 중 빠진 것, 명세에 없는데 추가된 것, 명세와 다르게 동작하는 것.

## 보지 않는다

- 의도와 무관하게 틀린 로직 → correctness
- 현재 phase 밖의 기능을 미리 만든 것 → architecture

## 읽을 문서

- `git log <merge-base>..HEAD --oneline`: 커밋 메시지 `feat(<phase>): step N — <이름>`에서 phase와 step을 찾는다.
- 그 step의 명세 `phases/<phase>/step<N>.md`의 `작업`, `Acceptance Criteria`, `금지사항`
- `docs/PRD.md`에서 변경이 닿는 기능만

변경에 대응하는 step 명세가 없으면 커밋 메시지와 PRD만으로 본다. 의도를 알 수 있는 자료가 없으면 `해당 없음`으로 보고한다.

## 체크 항목

1. 명세의 `작업`에 적힌 파일, 함수, 시그니처가 그대로 만들어졌는가? 빠진 것이 있는가?
2. 명세가 반드시 지키라고 한 핵심 규칙을 구현이 지키는가?
3. `금지사항`에 적힌 일을 했는가?
4. 명세에 없는 동작이나 파일이 추가됐는가?
5. 커밋 메시지가 말하는 일과 diff가 하는 일이 같은가?
6. 사용자에게 보이는 동작이 PRD와 같은가? 요금제 표의 무료·Pro 범위, 금액 표기(`1,234,000원`), 지원 파일 형식.
7. 테스트 이름이 말하는 동작과 테스트가 실제로 확인하는 동작이 같은가?
8. `phases/<phase>/index.json`의 `summary`가 실제 산출물과 맞는가?
