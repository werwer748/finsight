# security — 주입·인증·권한·시크릿

누가 무엇에 접근할 수 있는지와, 바깥에서 들어온 입력을 어떻게 막는지 본다.

## 본다

- 인증, 권한, 사용자 간 데이터 격리, 시크릿, 외부 입력 방어.

## 보지 않는다

- 민감 데이터가 LLM이나 로그로 나가는지 → privacy
- 서버 코드 안에서 레이어 위치가 맞는지 → architecture

## 읽을 문서

- `CLAUDE.md`의 CRITICAL 중 서버 전용 호출, RLS, 권한 체크 규칙 (이미 컨텍스트에 있다)
- `docs/ADR.md`에서 변경이 닿는 것만: ADR-002(RLS), ADR-010(사용자별 캐시, secret key 없음), ADR-011(업로드 상한), ADR-013(업로드 파일 방어)

## 체크 항목

1. `"use client"` 파일이나 그 파일이 import하는 모듈에서 Supabase·Polar·Claude를 직접 호출하는가? 🔴
2. 시크릿이 클라이언트로 나가는가? `NEXT_PUBLIC_`이 붙은 비밀 값, 클라이언트 번들에 들어가는 모듈의 서버 전용 환경변수, 응답이나 로그에 담긴 키. 🔴
3. 사용자 데이터를 담는 새 테이블에 RLS가 켜져 있고 정책이 `user_id`로 격리하는가? RLS를 우회하는 secret key를 쓰는가? 🔴
4. 서버 액션과 라우트 핸들러가 요청마다 세션을 확인하는가? 클라이언트가 보낸 `user_id`를 그대로 믿는가?
5. 무료·Pro 권한을 서버에서 확인하는가? 화면에서 숨기기만 하면 🔴다.
6. 리다이렉트 대상, 쿼리 문자열, 폼 값 같은 외부 입력을 검증하는가? (오픈 리다이렉트, SQL·HTML 주입)
7. 업로드 파일을 ADR-013대로 방어하는가? 앞쪽 바이트로 형식을 판별하고, 압축을 푼 크기 20MB와 시트 20개를 넘으면 거부하고, ZIP64와 크기가 다르게 적힌 파일을 거부한다.
8. 업로드 남용 방지 상한(사용자별 24시간 20회)이 서버에서 적용되는가? (ADR-011)
9. 웹훅이 서명을 검증하는가?
10. 오류 응답이 내부 정보(스택, 쿼리, 키)를 드러내는가?
