# privacy — 민감 데이터 처리

거래 내역은 금융 정보다. 민감한 값이 어디로 흘러가는지 본다.

## 본다

- LLM으로 나가는 데이터, 로그, 오류 메시지, DB에 저장하는 값, 응답과 화면에 실리는 값.

## 보지 않는다

- 다른 사용자가 데이터에 접근할 수 있는지(RLS, 권한) → security

## 읽을 문서

- `CLAUDE.md`의 CRITICAL 중 LLM 전송 규칙 (이미 컨텍스트에 있다)
- `docs/ADR.md`에서 변경이 닿는 것만: ADR-004, ADR-012, ADR-014

## 체크 항목

1. Claude에 보내는 내용이 가맹점명과 집계된 통계뿐인가? 계좌·카드번호, 이름, 원본 거래 행이 들어가면 🔴다.
2. 은행 내역에서 카드 결제로 확인되지 않은 행의 내용이 캐시 조회나 Claude 호출로 넘어가는가? (ADR-012) 🔴
3. 가맹점명을 보내기 전에 숫자 4개 이상이 든 숫자·하이픈 구간을 가리는가? (ADR-012)
4. `console.log`, 오류 객체, 예외 메시지에 거래 행, 적요, 이메일 같은 값이 실리는가?
5. 계좌번호나 카드번호를 파일에서 꺼내거나 저장하는가? 시각을 DB에 저장하는가? ADR-014는 둘 다 하지 않기로 했다.
6. 응답이나 화면에 필요 이상의 필드가 실리는가? (조회한 행 전체를 클라이언트로 넘기는 경우)
7. 프롬프트, 샘플 데이터, 테스트 픽스처에 실제처럼 보이는 개인 정보가 들어 있는가?
8. 데이터를 바깥으로 보내는 곳(분석 도구, 오류 수집 서비스)이 새로 생겼는가?
